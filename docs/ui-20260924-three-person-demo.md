# 三人共享打卡桌面端静态Demo方案

日期：2026-09-24

范围：只定义三人版主视图、成员概览、每日总结和移动端适配。保留现有暖纸、打卡票据、墨蓝和朱红语言；不改应用代码、数据库、成员关系或权限规则。静态Demo中的第三名成员使用中性占位姓名和状态。

## 2. 设计依据

### Design Thinking

- Purpose：三位彼此熟悉的成员在同一天内查看自己和另外两人的时段进展，快速确认谁正在做、谁已完成、谁需要被提醒。
- Tone：延续工业打卡钟与文具印章，三人并列像同一张打孔排班表上的三联票，不引入社交应用常见的彩色头像墙或数据大屏。
- Constraints：Next.js、TailwindCSS、shadcn/ui和现有组件边界不变；静态Demo以1440px桌面宽度呈现；移动端不能横向滚动，正文不低于`--text-lg`。
- Differentiation：三个人的进度不是三张泛化仪表盘卡片，而是同一张暖纸工作台上的三联票据。姓名、打孔条、当下状态和时段清单沿同一竖线对齐，阅读顺序像横向扫过一张考勤表。

### 新增视觉决策

- Typography：继续使用文楷和等宽数字。三人增加后，数字集中到完成数和时长，减少长句，保证三栏中的扫描效率。
- Color&Theme：不新增成员专属色。三人均用同一墨蓝完成语义，朱红只表达逾期或未完成，避免身份和状态混用。
- Motion：只保留既有盖章、实时更新闪底和抽屉过渡。三栏首次以60ms交错进入，每栏最多前8张卡参与，避免整页同时跳动。
- SpatialComposition：用顶部日期票据与三张成员概览票形成横向票根，主体三联等宽列对齐，打破普通三卡仪表盘的排列。
- Backgrounds&VisualDetails：延续暖纸点阵、虚线分割和打孔条。第三人不增加头像装饰、渐变或玻璃效果。

## 3. 信息层级方案

|层级|元素|视觉权重|
|---|---|---|
|第一层|日期票据中的日期、三位成员各自的当前状态和完成数|日期用`--font-display`+`--text-2xl`；完成数用`--font-mono`+`--text-xl`+`--color-text-primary`；逾期状态额外配Clock图标和`--color-danger`|
|第二层|成员姓名、打孔条、正在进行的任务、时段时间与任务名、每日总结四项指标|姓名和任务名用`--font-display`+`--text-lg`；时间与统计数字用`--font-mono`+`--text-lg`；进行中使用`--color-accent`边框和弱底|
|第三层|查看日期模式、已打卡时间、备注、留言板操作、总结备注时间线|`--text-sm`或`--text-base`配`--color-text-muted`；交互入口维持44px有效点击区|

为什么：三人并列时，先识别状态和进度，再下钻具体任务。仅用色彩不足以区分，姓名、数字位置、图标和文字共同承担层级。

### 4.2 断点行为

|宽度|布局|

## 6. 每日总结三人版

```text
┌────────────────────────9月24日总结────────────────────────┐
│ 完成情况                                                     │
│            [我]             [成员A]          [成员B]        │
│ 完成率       75%              88%              57%          │
│ 完成数       6/8              7/8              4/7          │
│ 拖延次数     1次              0次              2次          │
│ 拖延时长     30分             0分              1小时10分    │
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─              │
│ 备注，三位成员按打卡时间合并为一条时间线                     │
└────────────────────────────────────────────────────────────┘
```

- 比较规则沿用现有逻辑：完成率和完成数取较高值，拖延次数和拖延时长取较低值；三人同值时均显示主文字色。
- 不增加名次、奖牌、总分或一句话裁定。共享监督强调信息对照，不制造三人竞赛压力。
- 移动端总结不横向滚动：比较表改为三个紧凑成员块纵向排列，每块内部四项标签数值两列。摘要入口仍在日期票据内。
- 未来日期所有拖延数据按现有未来预览口径呈现，不能用朱红模拟未发生的失败。

为什么：四项指标和现有汇总函数完全一致，变化只在比较维度从两列扩展为三列。保持指标不变可让老用户快速迁移阅读习惯。

## 7. 交互与动效规范

- 首次进入：日期票据先出现，三张成员概览随后按左到右60ms交错淡入上移，使用`--duration-normal`和`--easing-default`。时段卡沿既有列表交错规则。
- 实时同步：任何成员打卡，所在成员概览打孔条和对应时段卡同步更新。完成章使用既有`--duration-slow`+`--easing-spring`落章；概览卡仅闪`--color-accent-subtle`后在250ms回落。
- 逾期切换：状态文字、Clock图标和朱红左线一起在`--duration-normal`内淡入。朱红只标状态，不用三种成员颜色区分来源。
- 页签切换：内容淡出150ms后淡入250ms，使用`--easing-default`；不对每次切换重复卡片交错入场。
- 总结抽屉：沿用底部上滑入400ms、下滑出250ms；对比表数值变更用150ms淡变，不做数字滚动。
- Loading：成员概览用与现有`Skeleton`一致的高156px票据骨架，时段区保持三列或单页签骨架；加载失败需保留区域高度并显示图标、文字和重试入口。
- `prefers-reduced-motion`：取消成员卡位移和盖章弹性，改为150ms透明度变化；`MessageBoard`继续使用它现有的组件级静态降级分支。

## 8. 自检与实施约束

### 工程正确性

- 可访问性：正文与背景继续使用既有对比度token；逾期同时有Clock、时长和文字；所有可操作成员概览和页签均有可见focus ring。
- 触控：移动端页签、关闭、写留言和成员概览的有效点击区不低于44px，相邻目标保持至少8px间距。
- 导航：移动端页签固定三项，当前项明确高亮；点击成员概览只切换页签，不改变日期或路由。
- 表单与反馈：本方案不新增表单；沿用留言输入的可见标题、就近错误和提交loading。错误状态包含图标、文字和边框或底色变化。
- 响应式与中文：1200px以下不把三栏硬压；移动端正文维持`--text-lg`；姓名、任务名、备注都有明确截断策略，避免中文单字孤行。
- 图表：无新增图表。每日总结是数据表，列名、成员头像和指标文字共同表达含义。

### 反套路与一致性

- 不新增字体、色相、渐变、玻璃卡或成员专属色，延续项目的文楷、等宽数字、暖纸点阵和票据虚线。
- 去色后，日期、完成数、列标题、时间和任务名仍能区分层级；三栏列头和卡片结构完全一致。
- 全页色相仍为墨蓝、朱红、暖黄警告三类语义色，未超过项目既有色相预算。
- 暖纸工作台上的三联票据是共享打卡题材专属表达，不使用三等分数据大屏或通用仪表盘卡片。

## 9. 待决策项

1. 真实三人数据接入前需确认成员关系、第三位成员的读写权限和Realtime订阅范围。当前`app/page.tsx`只维护我与单一对方视图，本方案不改这部分。
2. 第三人是否与前两人同样拥有模板和时段编辑权，需要产品规则确认。静态Demo默认仅本人列可编辑，其他两列只读。
3. 成员姓名最大显示长度建议保持12个汉字桌面、4个汉字移动。超出时截断并提供完整无障碍名称，避免为极长昵称破坏三列对齐。
4. 768至1199px采用两列加一列换行保护布局。若必须让1024px也三人同排，需要接受每列压缩并重新验证`SlotCard`任务名与打卡控件的可读性，本方案不采纳。
